# AGENTS.md

Docusaurus documentation site for the **Global Lighting Data Format (GLDF)** — [gldf.io](https://gldf.io). Content-heavy repo: most edits are Markdown pages, not application code. React 19, Node >= 20, npm only (`yarn.lock` is gitignored; install with `npm ci`).

## Commands

- `npm ci` — install dependencies
- `npm start` — dev server (`npm start -- --host 0.0.0.0` for LAN access)
- `npm run build` — production build; **this is the only automated check** (no tests/lint/typecheck scripts exist; CI runs exactly this)
- `npm run serve` — serve the built site locally
- `npm run clear` — clear the Docusaurus cache when builds behave strangely
- `npm run write-heading-ids` — insert heading anchors into Markdown files

## Layout

- `docs/` — documentation pages (77 .md files), organized by topic: `overview/`, `getting-started/`, `structure/`, `container/`, `conventions/`, `geometry/`, `tips/`, `tools-dev/`, `contribute/`
- `blog/` — posts named `YYYY-MM-DD-title.md`; authors in `blog/authors.yml`
- `src/pages/` — standalone pages (homepage `index.js`, `imprint.js`, `download.md`, `privacy-policy.md`, etc.)
- `src/css/` — three stylesheets registered in `docusaurus.config.js` (`custom.css`, `index.css`, `imprint.css`)
- `static/` — served at site root: `img/`, `xsd/` (GLDF/L3D/meta/p3d schema files), `xsd-reference/` (generated XSD reference HTML — linked from the navbar, do not hand-edit), `other/` (downloadable example files like `example.gldf`)
- `sidebars.js` — sidebar definition
- `docusaurus.config.js` — site config (navbar, footer, Algolia search, Prism themes)

## Rules and gotchas

- **The docs sidebar is fully manual** (`sidebars.js`, not autogenerated). A new page in `docs/` is invisible until added there.
- Markdownlint config (`.markdownlint.json`): line length (MD013) is off; inline HTML (MD033) is only allowed for `img`, `br`, `div` — do not introduce other raw HTML tags in Markdown.
- `docusaurus.config.js` runs with `future: { v4: true }` and `@ts-check` JSDoc typing — keep editor types valid.
- Broken Markdown links/images are configured as `warn`, not `throw`, so a green build does not prove links are correct — check changed links yourself.
- Blog front matter: `onInlineTags`/`onInlineAuthors`/`onUntruncatedBlogPosts` are warnings; use `authors.yml` for authors.
- English only (`i18n.locales: ['en']`); `editUrl` points at the `master` branch.

## Branching and deployment

- `develop` is the working branch; `master` is release-only. Both run a test build (`npm ci && npm run build`, Node 20.x) on pull requests.
- Push to `master` auto-deploys to GitHub Pages via SSH (`npm run deploy`, secret `GH_PAGES_DEPLOY`).
- The test system (test.gldf.io) is **not** deployed by CI: a Docker image (`dialgmbh/gldf-website:latest`) is built and pushed manually; Caddy (`Caddyfile`, basic auth) serves it. Docker build = `npm ci && npm run build` in a `node:24-bookworm-slim` stage, copied into `caddy:2.11.2-alpine`.
